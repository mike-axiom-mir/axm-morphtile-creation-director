ROOT ARCHITECTURE

MorphTile core should understand/run ordinary MorphTile matter.

Creation machines sit NEXT TO MorphTile.

Rule:

IF A COMPONENT IS REQUIRED TO UNDERSTAND OR RUN ORDINARY MORPHTILE MATTER:
    it belongs in MorphTile core.

IF A COMPONENT HELPS INVENT, CREATE, IMPROVE, ASSEMBLE OR VERIFY MORPHTILE MATTER:
    it belongs in a creation machine.

Dependency direction:

    machines ---> MorphTile public contracts

NOT:

    MorphTile ---> official AXM machines

MorphTile must remain usable without any AXM creation machine installed.

Third parties must eventually be able to build compatible machines without becoming part of AXM or modifying MorphTile core.

============================================================
PROVISIONAL MACHINE ENVELOPE
============================================================

Do not overdesign this.

Use a minimal provisional concept approximately like:

REQUEST
- request id
- goal / intent
- input MorphTile matter or references when needed
- constraints
- available vocabulary/capabilities
- budget
- caller/provenance

RESULT
- request id
- machine id/version
- status
- candidate output
- dependencies
- evidence
- warnings/HOLDs
- provenance
- optional suggested missing capability

Important:
Candidate output is NOT automatically canonical.

Machine output should be suitable for MorphTile's existing safety path:
clone -> plan -> commit -> receipt -> rollback

A machine must be allowed to answer:
HOLD / CANNOT SATISFY / MISSING CAPABILITY

Never force fabricated output merely to return success.

============================================================
THIRD-PARTY COMPATIBILITY
============================================================

This is a first-class architectural goal.

Official AXM machines must NOT receive secret privileges required to make valid MorphTile matter.

Long-term desired shape:

third-party machine
    -> valid candidate MorphTile matter
    -> standard verification
    -> normal MorphTile safety/merge path
    -> works

If a third party invents a better geometry, animation, interface, CAD, audio, physics or other creation machine, that should expand what people can create with MorphTile rather than require us to absorb their implementation into MorphTile core.

MorphTile owns/defines the interoperable matter contracts.
AXM does not need to own every producer.

============================================================
REPOSITORY ISOLATION
============================================================

One machine failing must not break the others.

Avoid:
- shared mutable internals;
- copy-pasted hidden state;
- circular dependencies;
- importing entire sibling repositories;
- sibling repo writes;
- assumptions that every machine is installed.

Prefer:
- explicit data packets;
- fixtures;
- versioned manifests;
- adapters at boundaries;
- contract tests.

A machine can evolve or be replaced independently.
